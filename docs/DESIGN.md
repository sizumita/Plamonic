# Plamonic 設計書

Plamonic は、macOS の Accessibility API（AX）で他アプリの画面上のテキストを読み取り、
PLaMo 3 Translate（MLX-4bit）をアプリ内でネイティブに動かして翻訳し、
元のテキストの位置に訳文を重ねて表示するメニューバー常駐アプリ。

参考:
- Yappli Tech Blog「Slack と Discord のメッセージを全文翻訳する」: AX で要素ツリーを辿り、要素と同じ位置・サイズの
  ウインドウを重ねる方式。Discord の roleDescription は言語設定で変わるので注意、インライン要素は共通の親でまとめる。
- kat0h の gist（plamo-ja-v2）: PLaMo 3 Translate へのリクエスト形式、履歴の渡し方、stop トークン、`looks_wrong` による再試行。

## 1. 全体構成

```
Plamonic.app (AppKit + SwiftUI, LSUIElement, 非サンドボックス)
├── App/            メニューバー、起動処理、権限オンボーディング
├── Core/           モジュール間の共有型（設定モデル、セグメント、オーバーレイ項目）  ← 契約
├── Accessibility/  AXUIElement の薄いラッパー、一括属性取得、Electron 有効化、ウインドウ ID
├── Extraction/     AX ツリー → 翻訳単位（TextSegment）への変換、アプリ別ルール、可視判定
├── Settings/       設定の永続化（JSON）、既知アプリのプリセット、SwiftUI 設定画面
├── Overlay/        訳文を重ねる透明ウインドウ、文字サイズ自動調整、ホバー表示
├── Translation/    翻訳キャッシュ、言語判定、段階翻訳（下書き→仕上げ）のスケジューラ
├── Session/        リアルタイムループ（走査→差分→翻訳依頼→描画）、アプリ切替追跡
├── Hotkeys/        グローバルホットキー（Carbon RegisterEventHotKey）
├── Updates/        Sparkle 2 によるアップデート（フィードの選択、設定、--update-probe）。7.1
└── Bridge/         ブラウザ拡張機能（Safari・Chrome）からの翻訳依頼を受けるソケット。9 章

Packages/PlamoKit (Swift Package, mlx-swift 0.32.3 のみに依存)
├── PlamoTokenizer      tokenization_plamo.py の移植（Aho-Corasick + Viterbi、バイトフォールバック）
├── PlamoPromptBuilder  PFML3 プロンプト生成（chat_template.jinja と同じ出力）
├── Plamo3Model         modeling_plamo_mlx.py の移植（RMSNorm offset、SourceRoPE、SWA/全体注意）
├── PlamoGenerator      prefill + 貪欲デコード、ストリーミング、停止トークン、プレフィックス KV 再利用
├── PlamoModelStore     Hugging Face からのダウンロード、配置、削除
└── PlamoTranslationEngine (actor) 複数モデルのロード管理、直列実行、アイドル時アンロード
plamo-cli               コマンドラインツール（tokenize / translate / bench / download / verify / list）
```

## 2. PLaMo 3 Translate（MLX）

- リポジトリ: `pfnet/plamo-3-translate-{0.8b,2b,8b,31b}-MLX-4bit`。サイズはおよそ 0.98 / 2.41 / 6.07 / 18.66 GB。
- 0.8B 軽量版: `sizumita/plamo-3-translate-0.8b-mlx-4bit-compact`（約 0.5 GB）。PFN の 0.8B（BF16）を mlx-lm 0.32.2 で
  全層 4bit（group 64）に変換した非公式の派生モデル。公式版との違いは `embed_tokens` と `lm_head` も量子化していること
  （スケールは BF16）と、`config.json` に `plamo_rope_inv_freq` がなく Hugging Face 形式の `rope_parameters` を持つこと。
  `plamo_rope_inv_freq` がないときは `rope_parameters`（`full_attention` は yarn、`sliding_attention` は default）から
  transformers と同じ式を float32 で計算する（公式の表と 1 ulp 以内で一致）。
  M4 での実測（`plamo-cli bench`）: 重み 964 → 478 MB、読み込み直後のプロセス 1,164 → 632 MB、
  446 トークンの入力でのピーク 1,781 → 1,056 MB。参考訳 8 件のうち 6 件が公式版と同じ訳、2 件は言い回しだけ違う。
  モデルの大きさは 0.8B と同じなので、段階翻訳ではどちらも相手より小さいとは扱わない（`ModelSize.rank`）。
- 必要ファイル: `config.json`, `tokenizer.jsonl`, `tokenizer_config.json`, `special_tokens_map.json`,
  `generation_config.json`, `model.safetensors` または `model-0000N-of-0000M.safetensors` + `model.safetensors.index.json`。
- 保存先: `~/Library/Application Support/Plamonic/Models/<リポジトリ>/`（例: `pfnet/plamo-3-translate-2b-MLX-4bit/`）（ダウンロード完了時に `.complete` を置く）。
- ダウンロード: 隣の `.<repo名>.partial/` に集め、検証が済んだファイルは `.downloaded.json`（パス → oid）に記録する。
  一時的なネットワークエラー（接続断・タイムアウト・HTTP 5xx / 429・サイズ不一致）はファイルごとに 2 / 5 / 10 秒後に再試行する。
  それでも失敗したら `.partial` を残し、次のダウンロードは oid とサイズ（safetensors はヘッダも）が一覧と一致するファイルを
  再利用して続きから始める（一致しないものは消す）。キャンセル・モデルの削除・揃ったファイルの検証失敗では `.partial` を消す。
  `.complete` は全ファイルが揃って検証に通り、本来の場所へ移したときだけ書く。設定の「モデル」は残っている `.partial` の
  サイズを表示し、「続きからダウンロード」と「削除」を出す。
- 読み込み時の検証: `config.json` の値（各サイズの範囲、heads と KV heads の整除、量子化の bits / group_size）と、
  すべての重みの形・dtype を突き合わせる（量子化重みは uint32 `[out, in·bits/32]`、scales / biases は `[out, in/group]`）。
  index の shard 名は同じディレクトリの `.safetensors` だけを許す。合わないモデルは C++ 側で落ちる前に
  `PlamoError.invalidModel`（「モデルファイルを読み込めません: …」）になる。ウォームアップも `withError` の中で行う。
- 特殊トークン: unk=0, bos=1, eos=2, pad=3, tag=16, key=17, val=18, msg=19, index=20, item=21。
- 生成停止: トークン 1（`<|plamo:bos|>`）または 16（`<|plamo:tag|>`）。temperature 0（argmax）。
- `add_bos_token = true`: プロンプト先頭に bos（id 1）を付ける。

### 2.1 PFML3 プロンプト（chat_template.jinja と同一）

```
<|plamo:bos|><|plamo:tag|>dataset<|plamo:msg|>translation
[<|plamo:tag|>context<|plamo:msg|>{context}]                         context が空でなければ
{履歴ごとに}
  <|plamo:tag|>input[<|plamo:key|>lang<|plamo:val|>{source_lang}]<|plamo:msg|>{過去の原文}
  <|plamo:tag|>output<|plamo:key|>lang<|plamo:val|>{target_lang}<|plamo:msg|>{過去の訳文}
[<|plamo:tag|>glossary{<|plamo:index|>{原語}<|plamo:item|>{訳語}}...]   用語集が空でなければ
<|plamo:tag|>input[<|plamo:key|>lang<|plamo:val|>{source_lang}]<|plamo:msg|>{原文}
<|plamo:tag|>output<|plamo:key|>lang<|plamo:val|>{target_lang}[<|plamo:key|>form<|plamo:val|>{plain|polite}]<|plamo:msg|>
```
（実際は改行なしで連結）

- target_lang: `ja`, `en`, `zh-hans`, `zh-hant`, `ko`, … 53 言語 + `ja(easy)`（やさしい日本語）。
- form は target_lang が `ja` のときだけ有効。
- 原文・context・用語集に `<|plamo:` を含めてはいけない（含まれる場合は除去またはエスケープ）。
- 入力+出力は 32768 トークン以内（アプリでは既定 4096 程度に制限）。

### 2.2 モデル構造（modeling_plamo_mlx.py）

- `model.embed_tokens`（非量子化 bf16）、`model.layers.layers.{i}.{mixer,mlp,pre_mixer_norm,post_mixer_norm,pre_mlp_norm,post_mlp_norm}`、`model.norm`、`lm_head`（非量子化。31B は tie_word_embeddings=true で embed_tokens を流用）。
- `mixer.qkv_proj`, `mixer.o_proj`, `mlp.gate_up_proj`, `mlp.down_proj` は 4bit affine 量子化（group 64）。スケールは FP16。
  量子化 Linear の出力は `.asType(入力 dtype)` で元の dtype に戻す（BF16×FP16 で FP32 に昇格するため）。
- RMSNorm: `float32 で正規化 → 入力 dtype に戻す → (weight + offset) を掛ける`。
  offset: pre_* と q_norm/k_norm と model.norm は 1.0、post_mixer_norm は 1/5、post_mlp_norm は 1/5^1.5。
- 注意: `(layer_idx + 1) % sliding_window_pattern == 0` の層が全体注意、それ以外は窓 2048 のスライディング窓注意。
- RoPE: `config.plamo_rope_inv_freq.full / .local`（各 64 個の FP32 値）を使う。全体注意層は
  `concentration = 1 + 0.1 * ln(rope_scaling_factor)`、スライディング層は 1.0。
  `phase = (arange(L) + offset)[..., None] * inv_freq; phase = concat([phase, phase]);
   cos = cos(phase).asType(x.dtype) * conc; sin = 同様; rotated = concat([-x[..., half:], x[..., :half]]); x*cos + rotated*sin`
- MLP: `gate, value = split(gate_up_proj(x), 2)`、`silu は float32 で計算して gate dtype に戻す`、`down_proj(act * value)`。
- 出力ロジットは float32。

| 項目 | 内容 |

| 粒度 | 段落（インライン要素を親でまとめる）/ 要素ごと / 項目ごと（マッチした項目内を 1 つに） |
| UI 部品も訳す | ボタン・メニュー等のタイトル |
| 編集可能テキストも訳す | テキストフィールドなど（パスワード欄は常に除外） |
| 翻訳先言語・文体の上書き | |
| 文脈（context） | 例:「エンジニア同士の Slack の会話」→ PFML3 の context に渡す |
| アプリ別用語集 | グローバル用語集とマージ |
| 表示スタイルの上書き | |
| 段階翻訳の上書き | 全体の設定に従う / 使う / 使わない（下書きモデルと混雑時の一時停止は全体の設定） |
| 会話履歴を使う | 直前のメッセージの原文/訳文を履歴として渡す（チャット向け、遅くなる） |
| AXManualAccessibility | Electron/Chromium の AX ツリーを有効化 |
| AXEnhancedUserInterface | 一部アプリで必要（ウインドウアニメーションに副作用あり、既定オフ） |

AXManualAccessibility / AXEnhancedUserInterface は、設定する前に値を読み、Plamonic が自分でオンにしたものだけを覚える。
そのアプリの動作がオフになったとき（全体の無効化を含む。追跡中でない背面アプリも対象）、セッションの停止時、終了時に
オフへ戻す（AX 呼び出しなので走査キューで行う。終了時はメインスレッド）。アプリを切り替えるたびには戻さない
（Chromium は再びオンにするとツリーを作り直し、数秒のウォームアップが要るため）。プロファイルのスイッチを切った場合は
次の走査で戻す。もともとオンだった属性と、AXEnhancedUserInterface がオン（VoiceOver など）のときの
AXManualAccessibility は戻さない。ウォームアップ（3 秒）は実際に属性をオンにしたときだけ始まる。

設定ファイルの読み込みは寛容: 欠けたキーは既定値になる（ネストした抽出ルール・マッチャ・見た目も同じ）。
型の合わない値はその項目だけを捨てて残りを読む（`settings.corrupt-*.json` に退避）。

プリセット: Slack, Discord, Safari, Google Chrome, メッセージ, Mail, Microsoft Teams など。
- Slack: 項目 = DOM クラス `p-rich_text_section` / `p-rich_text_list` / `p-rich_text_quote`、除外 = `p-rich_text_preformatted`。
  メッセージは `AXGroup/AXDocument`（roleDescription "message"）。
- Discord: 項目 = DOM クラス接頭辞 `messageContent_`、`embedDescription_`。メッセージは `AXGroup/AXDocumentArticle`
  （roleDescription はローカライズされるので使わない）。

抽出ルールのコンテナを指定していてもウインドウに見つからない場合、項目が指定されていればウインドウ全体から項目を探す
（時間切れで探索が途中だった場合は除く）。項目のないルールでは何も訳さない。これによって、Claude のプリセットは
チャット欄（`epitaxy-chat-panel-body`）のないチャットタブでも `font-user-message` / `font-claude-response` を拾う。
「マウス下」の範囲は、ポインタを含むセグメント、なければ 10pt 以内で最も近いもの 1 つだけを訳す。行間や余白の上では
何も訳さない。ウインドウ・Web 領域・スクロール領域などの大きな入れ物や、ウインドウの 25% を超えるブロックは選ばない。
「マウス下」と「フォーカス中の要素」では、訳文を読み取った要素の中に収め、同じブロックのほかの段落には重ねない（6 章）。

## 4. リアルタイムループ

1. **対象の決定**: 前面アプリ（NSWorkspace の activate 通知）。「切替後も続ける」が有効なら、直近に翻訳したアプリの
   画面上のウインドウも対象に残す（背面は長い間隔で走査）。
2. **走査**（バックグラウンドの直列キュー）: `AXUIElementCopyMultipleAttributeValues` で 1 要素 1 IPC。
   実測で 400〜1700 要素のウインドウ全体が 25〜75ms。ルール指定時はコンテナ要素を覚えておき、その部分木だけ辿る。
   画面外（クリップ矩形と交差しない / 高さ 3pt 未満）の部分木は辿らない。時間・要素数の上限あり。
   上限で途中までになった走査が前回より少ない文章しか見つけなかったときは、前回の表示を残す（3 回続くまで。
   スクロールの直後は位置が古いので、見つかった分をすぐ使う）。数えるのは文章が減った途中の走査だけで、
   前回と同じだけ見つけた途中の走査は完全な走査と同じに扱う（負荷の高いときに、減った走査をそのまま使うと
   訳しかけの翻訳が取り消され、戻ってきた文章が新しく現れたと数えられて仕上げが止まるため）。
   それでも途中までの走査を使うときは、届かなかった文章を「まだ画面にあるはず」として翻訳側が覚えておく。
   その文章の訳しかけは取り消さず、戻ってきても新しく現れたと数えず、現れた順番も変えない。次の完全な走査で忘れる
   （512 件を超えたらすべて忘れる）。
3. **分割と抽出**: 段落粒度では「子がすべてインライン（AXStaticText, AXLink, AXImage など）」の要素を 1 ブロックに
   まとめる（Slack の p-rich_text_section、Discord の messageContent）。ネイティブの AXTextArea は改行で段落に分け、
   `AXBoundsForRange` で各段落の矩形を得る。
4. **フィルタ**: 空白・数字・記号・絵文字だけ、URL・パス・コードらしいもの、最小文字数未満、翻訳先と同じ言語
   （NLLanguageRecognizer、「同じ言語も翻訳」なら残す）を除外。
5. **差分と依頼**: セグメントの原文をキーにキャッシュを引き、無ければ翻訳ジョブを積む。
   優先度: 下書き（可視）> 仕上げ（下書きなし時）> 仕上げ（下書き済みの差し替え）。画面から消えたセグメントのジョブは破棄。
6. **描画**: ウインドウごとに 1 枚の透明パネル（クリック透過）を対象ウインドウの直上に重ね、各セグメントの矩形に
   訳文を描く。原文の大きさ・行間・色が分かればそれで書き（6 章）、分からなければ矩形に収まるよう自動調整（最小〜最大）。
   生成中は少し薄く、下書きは小さな点で示す。訳文のリンクと、訳文で覆った原文のリンクの上にだけ、クリックを受ける
   小さなパネルを置く（6.1）。
7. **イベント**: AXObserver（値変更・ウインドウ移動/リサイズ・フォーカス変更・要素破棄）と、グローバルな
   スクロール/マウス/修飾キーの監視で、即時再走査・一時非表示・原文表示を行う。ウインドウ系のイベントが続くとき
   （ライブリサイズなど）も走査は 0.15 秒以上空ける。規則のコンテナが見つかったウインドウでは、各コンテナの
   見えている範囲を別々にスクロールする領域とみなし、スクロールした領域の訳文だけを隠す（Claude のメインのチャットと
   サイドチャット）。どの領域でもない場所（スレッド一覧など）のスクロールでは何も隠さず、止まったら 1 回だけ読み直す。
   コンテナがないウインドウと、領域が 1 つだけのときは、これまでどおりウインドウの訳文をまとめて隠す。
   選択テキストの吹き出しも、そのウインドウのスクロール中は隠し、次の走査で新しい位置へ動かしてから表示し直す。マウスの移動は、オーバーレイが求めている間だけ監視する（6.1）。
8. **応答しないアプリ**: 走査はすべて 1 本の直列キューで行うので、応答しないアプリがあると他のアプリの走査も
   AX のタイムアウト分だけ遅れる。走査が `.unavailable` で終わったアプリは 0.5 秒から倍々に最大 4 秒まで走査を止める
   （応答があれば解除。「今すぐ翻訳」と前面への切り替えでも解除）。AX 通知の登録も、最初のタイムアウトで打ち切る。
9. **パスワードの入力中**: 何も読まない（4.1）。

座標: AX はプライマリスクリーン左上原点（y 下向き）。Cocoa はプライマリスクリーン左下原点。
`cocoaY = primaryScreenHeight - (axY + height)`。

### 4.1 パスワード入力中は読まない

パスワードを入力している間は、ほかのアプリのテキストも画面も読まない（`GlobalSettings.pauseDuringPasswordEntry`、
「一般」の「プライバシー」、既定オン。オフにすると止めない）。パスワード欄（role か subrole が `AXSecureTextField`）は
この設定に関係なく、抽出がいつも飛ばす。判定はどれもテキストを読まずに行う（`PasswordEntryGuard`、`PasswordEntryRules`）。

**a. セキュア入力**（`IsSecureEventInputEnabled()`、Carbon。非推奨ではない）がオン。
- 実測（macOS 27.0.1）: フラグは WindowServer の共有メモリの 1 バイトで、1 回約 10ns（IPC なし）。オン・オフは
  呼び出しから 1ms 前後で反映される。セッション辞書（`CGSessionCopyCurrentDictionary()`）の
  `kCGSSessionSecureInputPID` はオンの間だけあるが、指すのはセキュア入力をオンにしたプロセスではなく、オンにした
  ときに前面にあったアプリ。背面の補助プロセス（ウインドウなし、前面に出ない）がオンにしたときも、前面にあった
  アプリ（Discord、Chrome で確認）を指す。アプリを切り替えても変わらない（OpenRadar 48953777、Cursor の報告）。ロックの
  解除やスリープからの復帰のあとは loginwindow のことが多い。辞書の読み取りは 0.2〜0.7ms の IPC なので、フラグが
  オンのときだけ読む。
  このキーと `CGSSessionScreenIsLocked` はヘッダにない（文字列で読む）。
- そのため「背面のアプリが持つセキュア入力では止めない」は作れない（持ち主が分からない）。名指しされたプロセス
  （以下「名指し」）で次のように決める。
  - 画面のロック中（`CGSSessionScreenIsLocked`）: 止める。メニューは見えないのでアプリ名なし。loginwindow をロック
    画面と見なすのはロック中だけ。ロックしていないときの loginwindow はふつうの名指しと同じ（止める。アプリ名なし。
    持ったままの判定で外れる）。
  - 名指しがシステムのパスワード画面: 止める。SecurityAgent、authorizationhost、coreautha（Touch ID とパスワード）、
    ScreenSaverEngine / legacyScreenSaver、NetAuthAgent、WiFiAgent、UserNotificationCenter、AuthKitUIMacService、
    キーチェーンサークル通知、BluetoothUIServer、EscrowSecurityAlert（12 種。bundle ID、なければプロセス名で照合）。
  - 前面がターミナルモードで読むアプリ（Terminal / iTerm2）で、名指しがそのアプリか不明、かつフォーカス中の要素が
    端末の画面（AXTextArea。b と同じ 1 回の呼び出しで role を見る）: 止めない。ターミナルの「セキュアキーボード入力」
    はオンのままのことが多く、ターミナルはパスワードを表示しない。プロンプトは c で扱う。パスワードを表示にした欄や
    検索欄など、ほかの要素にフォーカスがあるときは止める（Electron アプリをターミナルモードにしたとき。Terminal や
    iTerm2 でも、セキュアキーボード入力がオンなら、検索欄にフォーカスがある間は止まる）。b を問い合わせないとき
    （キーを押さないと何も読まないとき）は止めない。走査の直前の判定は必ず問い合わせる。
    ターミナルの上に出た Touch ID のダイアログ（sudo）は、名指しが coreautha になると見て止める（未実測。推定）。
    ターミナルを「オフ」にしている（読まない）ときはこの例外はなく、前面にある間は止まる。
  - セキュア入力が続いている間に、前面のアプリが 3 つの違うアプリになった（例: A → B → C。A ↔ B の行き来は数えない。
    パスワード管理アプリの自動入力は A → 管理アプリ → A）ら、背面のアプリが持ったまま（stuck）と見なし、a では
    止めない（`StuckSecureInputTracker`。アプリ名を一度だけログに出す。システムのパスワード画面とロック中は数えない。
    フラグがオフになったら数え直す。読む対象のアプリがない間も数えたまま（そのときはフラグ（約 10ns、IPC なし）
    だけ見て、オフなら数え直す））。名指しは切り替えについてこないので、数えるのは前面のアプリ。パスワード欄を持つ
    アプリは背面に回るとセキュア入力を離すので、ふつうに入力していればこうならない。古い Chrome / Electron や
    パスワード管理アプリが持ったままにすると、こうしないと読み取りがずっと止まる。
  - それ以外（前面のアプリ、メニューバーのパスワード管理アプリ、エージェントのパスワード画面、ロックしていないときの
    loginwindow）: 止める。アプリ名は名指しの名前（loginwindow なら名前なし）、なければ前面のアプリの名前。

**b. パスワード欄にフォーカス**: 前面のアプリが読む対象（動作がオフでない）で、そのアプリの `AXFocusedUIElement` の
role か subrole が `AXSecureTextField`。
- 読む対象のアプリにだけ問い合わせる（ほかのアプリに問い合わせると、利用者がオフにした Chromium アプリの AX を
  起こしてしまうことがある）。それも前面にあるときだけ。Plamonic 自身のウインドウ（や bundle ID のないアプリ）が
  前面の間は、セッションは前のアプリを追い続けるが、b は問い合わせない（スモークテストの固定の対象は別）。a で
  止めている間は問い合わせない。
- AX のタイムアウトは 0.1 秒（アプリの要素と、返ってきた要素の両方に設定。タイムアウトは要素ごと）。
  role と subrole を 1 回の `AXUIElementCopyMultipleAttributeValues` で読み、値は読まない（伏せ字の値
  U+F79A / U+2022 でも長さがパスワードの長さと同じ）。アプリの要素は pid ごとに 1 つ覚える。
- 答えは 50ms 使い回す（1 回の走査のまとまり）。答えがない（タイムアウト）ときは前の答えを使い、1.5 秒は問い合わせない
  （応答しないアプリでは 1 回 100〜240ms かかり、戻った直後の 1 回もまだタイムアウトすることがある。実測）。
- 実測: 費用は中央値 0.2〜0.7ms（ときどき 30〜67ms）。AppKit も WebKit も role は `AXTextField` で subrole が
  `AXSecureTextField`。前面でない AppKit のアプリはフォーカス中のパスワード欄を返すが、前面でない WebKit と Chrome は
  noValue を返す（前面のアプリでだけ意味がある）。Chromium の「パスワードを表示」にした欄や CSS で隠した欄は
  subrole がないが、セキュア入力はオンになるので a で止まる。

**c. ターミナルのパスワードのプロンプト**（ターミナルモード、`TerminalPasswordPrompt`）: ウインドウの最後の行が
パスワードを待っていれば、そのウインドウだけ読み取りを止める。
- 抽出は `AXVisibleCharacterRange` と `AXSelectedTextRange` を 1 回の IPC で読む（可視範囲の読み取りに
  属性を 1 つ足すだけ）。挿入点の行（選択の長さが 0 で、後ろが縦の罫線か行末まで空白のとき、挿入点より前の文字）か、
  最後の空でない行がプロンプトで終わっていれば `WindowSnapshot.passwordPrompt`。挿入点を正しく返すかは端末に
  よって分からず、tmux などのステータス行がプロンプトの下にあることもあるので、両方を見る。AXValue は使わない。
- プロンプトの判定: 末尾の空白・罫線・`[input is hidden]`・入力の印（`*` `•` `●` など。sudo の pwfeedback）を除いて
  `:` か `：` で終わる。その前にパスワードの語（password, passphrase, passcode, PIN, Kennwort, mot de passe,
  contraseña, senha, пароль, パスワード, パスフレーズ, 暗証番号, 密码, 비밀번호 など）があり、語から `:` までは 120 文字
  以内で `: ` を含まない（`Password: hunter2` は違う）。行は 200 文字まで。英字とキリル文字の語は単独の語であること
  （前後に文字・数字・`_ / . - = ? & # % + ~ @` がない。`Passwords:`、`https://…/password:`、`password.txt:` は違う）。
  例: `Password:`、`[sudo] password for user:`、`[sudo] user のパスワード:`、`Enter passphrase for key '…':`、
  `Password for 'https://…':`、`Enter PIN for …:`、`パスワード：`、`Verify password:`、`user@host's password:`。
- 誤検出: `password` を含んで `:` で終わる散文の行（`To reset your password, run this:`）が最後の行だと、
  そのウインドウは次の変化まで止まる（害は小さい）。
- その走査の結果はそのまま使う（読んだのはプロンプトまで）。そのウインドウは時間での走査をやめる
  （`WindowTrack.promptPause`）。ふつうのプロンプトはパスワードを表示しないので、入力しても読み取りは起きない。
- 入力の印（`*` `•` `●`。sudo の pwfeedback、Inquirer 風の CLI）を出すプロンプトでは画面が変わる。抽出は
  プロンプトの行の末尾の印を空白にしてから分ける（`TerminalPasswordPrompt.blankingInput`。印は 1 文字 1 セルなので
  位置は変わらない）。印は訳文にもキャッシュにも入らず、印だけ増えても段落の文章は変わらない。
- 再開（1 回走査する。まだプロンプトなら止めたまま。sudo の「Sorry, try again.」）: そのアプリの AX 通知（種類を
  問わない）、アプリの切り替えなどの強制の走査、今すぐ翻訳、プローブが見た変化。走査が戻るまでは止めたまま
  （メニューの行も、Esc の監視を止めるのも）。通知で走査しないとき（訳を表示していない手動のアプリ）は、止めるのを
  やめる。
- プローブ: 前面の読む対象のアプリのフォーカス中の要素の `AXNumberOfCharacters` と `AXSelectedTextRange`（b と同じ
  1 回の AX 呼び出し）と、挿入点の前の 1 文字の `AXBoundsForRange`（1 回、タイムアウト 0.1 秒）。数と位置だけで、
  値もテキストも読まない。パスワード欄なら何も使わない。
- 挿入点がその行のまま、足された（消された）文字数と同じセル数だけ動いたときは、印の入力と見なす。そのフォーカス中の
  ウインドウのテキストの通知（`AXValueChanged`、`AXSelectedTextChanged`、`AXLayoutChanged`）は再開も走査もせず、
  プローブが決める。Return のあとの出力は行が変わるか、いちばん下の行ではスクロールして桁が合わない。改行の文字の
  枠は行の残りの幅なので、印とは見なさない（プロンプトの最後の文字の約 1.5 倍より広い文字は印ではない）。
- 挿入点が分からない端末では、文字数が変わるかテキストの通知が来たら走査する。テキストの変化で走査して、プロンプトの
  まま同じ文章だったら（印は空白にしてあるので、印だけ増えたとき）、印を出すプロンプトと見なす（そのウインドウで
  プローブが一度でも挿入点を見ていたら見なさない。走査の直後、プローブが測り直す前に来た通知でも）。そのウインドウの
  テキストの変化は、前の走査から max(2 秒, 背面の走査間隔) たつまで待ってまとめて 1 回読む。Return のあとの出力も
  そのとき読む（最大 2 秒遅れる。ウインドウやフォーカスの通知はすぐ読む）。走査の途中に来た変化は、出力かもしれない
  ので、もう 1 回走査する。
- 文字数が取れないアプリや背面のウインドウは、max(2 秒, 背面の走査間隔) ごとに走査する（読むのはプロンプトと、
  空白にした印まで）。
- メニューに出すのは、前面のアプリのフォーカス中のウインドウが止まっているときだけ。そのときは Esc の監視も止める。
- Terminal.app の振る舞い（実測）:
  - プロンプトで待っている間（`read -s` の sudo 風のプロンプト）、`AXSelectedTextRange` は挿入点（長さ 0、
    プロンプトの直後）を返し、`AXNumberOfCharacters` も取れる。待っている間は AX 通知を 1 つも出さないので、走査も
    起きない。出力が来ると、テキスト領域の `AXValueChanged` と `AXSelectedTextChanged`（とウインドウの
    `AXTitleChanged`）が出て、約 0.02 秒後の 1 回の走査で読み取りに戻る。
  - 入力の印（pwfeedback のような `*`）1 つで、文字数と挿入点が +1、前の文字の枠が 1 セル（9pt）右へ動き、行は
    変わらない（高さ 17pt）。`\b \b` では挿入点が −1 で、文字数は変わらない。Return では改行の文字の枠が行の残りの幅
    （405pt）になる。いちばん下の行では約 0.05 秒後に 1 行上へ動く（スクロール）。印ごとに出る通知は、テキスト領域の
    `AXSelectedTextChanged` と `AXValueChanged` だけ。
  - 前面のプロセスが変わると、ウインドウの名前が変わる（`AXTitleChanged`）。ウインドウの通知なので、そのたびに
    1 回走査する。本物の sudo は入力の間にプロセスを起こさないので、名前は変わらないはず（未実測）。
- 印を出すプロンプトでのスモークテスト（印の入力、消す、Return、「Sorry, try again.」、もう一度のプロンプト、出力）:
  印の入力では走査せず、Return と出力では 1 回ずつ走査し、2 回目のプロンプトでは止めたまま、最後の出力で読み取りに
  戻る。プロンプトの行は印を除いた文章で訳され、ログにも訳文にも印は出ない。走査の直後、プローブが測り直す前に来た
  テキストの通知では、もう 1 回走査することがある。

**a か b のときに止めるもの**
- AX の読み取りすべて: 自動・背面の走査、今すぐ翻訳、選択テキストの吹き出し、マウスの下（どれも走査）。走査の
  キューは要求ごとに AX を読む直前にもう一度判定する（`gate()`）。止める直前に積まれた走査は読まずに
  `.paused` で終わり、画面は何も変えない。
- 背景色を測るための画面の取り込み（`ScreenCaptureGate`、`OverlayColorSampleScheduler.setCapturesPaused`）。
  取り込みの順番を待ったあとと、取り込む直前にも確かめる。止めていた間に測れなかったものは失敗と数えない。
- Esc を見るグローバルな keyDown の監視（ほかのアプリで打ったキーが見えるため）。
- 今すぐ翻訳は何も読まない（ログに出す）。表示中の手動の訳や吹き出しを閉じることはできる（読まない）。

**止めないもの**: 表示済みの訳文（そのまま残る。スクロールでは隠れ、再開後の走査で戻る）、マウスの移動・スクロール・
修飾キーの監視（テキストを含まない）、積まれていた翻訳、利用者が押したときだけの AX（訳文のリンクを押す、
「要素を調べる」）。

**終わったとき**: すべての対象を強制して再走査し、Esc の監視と画面の取り込みを戻す。

**判定のタイミング**: 1 本の utility の直列キュー（メインスレッドで AX を呼ばない。フラグの読み取りも 1 本にまとめる）。
設定がオンで読む対象のアプリがある間は 0.25 秒ごと（フラグは約 10ns、辞書はオンのときだけ）。フォーカスの変化・
ウインドウの変化の AX 通知とアプリの切り替えでは、すぐに判定する。前面のアプリは NSWorkspace の activate 通知
（メインスレッド）から渡す。正しさはポーリングに頼らない（走査の直前の判定）。読む対象がないときはフラグだけ見る
（辞書も AX も呼ばない。走査の直前の判定は別）。ポーリングとフォーカス・切り替えでの判定が b を問い合わせるのは、
キーを押さなくても読むもの（自動のアプリ、表示中の手動の訳や吹き出し、今すぐ翻訳のやり直し）があるときだけ。何も
表示していない手動のアプリ（既定）では、走査の直前の判定だけが b を問い合わせる（止めている間はポーリングも
問い合わせて、終わりを見る）。

**メニュー**（`SessionStatus.passwordPause`）: a・b は「パスワード入力中のため、読み取りを止めています（<アプリ名>）」、
c は「<アプリ名> がパスワードを待っているため、このウインドウの読み取りを止めています」。

**ログ**: 理由とアプリ名（bundle ID、ウインドウ番号）だけ。欄の値やテキストは出さない。スモークテストは、止めた回数と
時間、読まずに終わった走査、プロンプトでの停止と再開をいつも出す。`--password-guard <秒>` は判定の間隔を変え
（既定 0.25 秒、0.05〜5 秒）、判定が変わるたびに中身（セキュア入力、名指し、前面のアプリ、欄、結果）を出す。

**限界**
- `kCGSSessionSecureInputPID` と `CGSSessionScreenIsLocked` は公開されていないキー。変わったら、名前とターミナルの
  例外とロック画面の判定だけが効かなくなる（止めるかどうかは公開のフラグで決める）。
- 持ったままのセキュア入力は、3 つの違うアプリに切り替えるまで読み取りを止める（メニューには名指しのアプリの名前。
  loginwindow なら名前なし）。逆に、0.25 秒の間隔のあいだにオフになった切り替えを見逃して、3 つのアプリで続けて
  パスワードを打つと、a では止まらなくなる（b と走査の直前の判定は効く）。
- 前面のターミナルでセキュアキーボード入力がオンのときは a が効かず、c（プロンプトのウインドウだけ）で止める。
  背面のウインドウは読み続ける。
- 挿入点（またはその前の文字の枠）が分からない端末で、入力の印を出すプロンプトは、最初の印で 1 回、そのあとは
  2 秒に 1 回まで読む（読むのはプロンプトまで。印は空白にするが、印の数は文字数から分かる）。挿入点が分かる端末でも、
  印で行が折り返したとき、画面をスクロールしたとき、ウインドウを動かしたときは 1 回読む。
- b は前面のアプリだけ。c は画面に出ているプロンプトの文字で決めるので、決まった言い方でないプロンプトや、画面の外に
  スクロールしたプロンプトは分からない（パスワードは表示されないので読まれはしない）。
- 実測していないもの: ロック画面、システムのパスワード画面、前面で入力中のパスワード欄、Terminal と iTerm2 の
  セキュアキーボード入力、iTerm2 のプロンプト、ターミナルのプロンプトで実際に入力したとき（エコーしないので通知も
  文字数の変化もないはず）、Chromium のレンダラーの AX を有効にしたときのパスワード欄の role。
- スモークテストで確かめたこと: 背面の補助プロセスが 0.4 秒だけセキュア入力をオンにすると、走査の直前の判定が
  ポーリングより先に気づいてその走査を読まずに終え、約 0.5 秒止めたあと（その間の走査は 0 回）、すべてを読み直す
  （名前は前面のアプリ）。前面に出さないテスト用の AppKit のウインドウでパスワード欄にフォーカスを移すと b で止まり、
  離すとすぐ読み直す。Terminal のプロンプトは c のとおり。パスワードのない Chrome のページでは、走査・翻訳・描画は
  止めないときと変わらない（止めた回数 0）。

## 5. 段階翻訳（下書き → 仕上げ）

段階翻訳は翻訳モデル（仕上げ）とは別に設定できる 1 つの機能（`GlobalSettings.progressive`）。
オフなら翻訳モデルだけで 1 回訳す。オンなら次のとおり。アプリごとに「全体に従う / 使う / 使わない」を上書きできる
（`AppProfile.progressiveOverride`。下書きモデルと混雑時の一時停止の設定は全体で 1 つ。推論エンジンが 1 本のため。
一時停止しているかどうかはアプリごと）。

- 下書きモデル（既定 0.8B、翻訳モデルより小さいもの）でまず訳して即表示（状態 = draft）。
- 翻訳モデル（例 2B / 8B）で同じ原文を訳し直し、完了したら差し替え（状態 = final）。
- 下書きモデルが翻訳モデル以上の大きさ、または入っていないときは 1 段で訳す（設定画面に理由を出す）。設定の正規化は
  下書きモデルを常に翻訳モデルより小さく保ち（翻訳モデルが 0.8B のときは同じ 0.8B = 1 段）、スイッチは変えない。
  計画の側でも「より小さいか」を確かめる（手で書き換えた設定ファイルに備える）。
  古い形式の設定ファイル（段階翻訳のスイッチがなく、`"draftModel"` キーで下書きモデルを持つ）は読み込み時に移す。
  モデル名ならオン、`null` ならオフ。ただし翻訳モデルが最小（0.8B）のときの `null` は、古い形式の正規化が書いた値で
  利用者の選択ではないので、オンのまま読む（翻訳モデルを大きくすると 2 段に戻る）。
  翻訳モデルが入っておらず下書きモデルだけ入っているときは、下書きだけで訳す。
- 計画（どのモデルで訳すか）はウインドウごとにそのアプリの実効設定から作る。
- キャッシュは (原文, 翻訳先の言語, 翻訳元の言語, 文体, 文脈, 用語集, モデル) ごと。表示時は final > draft の順に採用。
  言葉のリンクのある文章は、印付きの原文（6.1）をキーにする。
  ファイル形式は version 2（翻訳元を含む）で、version 1 のファイルは一度だけ無視され、次の書き込みで置き換わる。
  ファイルへの書き込みは多くても 30 秒に 1 回（終了時に残りを書く）で、起動時の読み込みはバックグラウンドで行う。
  件数の上限は設定値（1,000〜50,000）と「表示中の文章数 × 2 + 256」の大きいほう（表示中の訳文を追い出さない）。
- 用語集は訳語が空の用語を送らない（PLaMo は空の訳語を受け付けず、その原語を含む文章がずっと失敗するため）。
- 推論は 1 本の直列キュー（MLX の評価は直列化する）。下書きジョブを優先し、空いた時間に仕上げを進める。
  長い文章（複数チャンク）の仕上げの差し替えは、未翻訳の文章が現れるとチャンクの切れ目で譲り、その下書きを先に出す。
  中断した差し替えは済んだチャンクを覚えていて、次に選ばれたとき続きのチャンクから再開する。

### 5.1 混雑時の一時停止（バースト制御）

スクロールやメッセージの連投で、新しい文章が一度に大量に現れることがある。仕上げモデルの 1 回（2B で約 1 秒）が
走っている間、新しい文章は下書きを待たされる。そこで、新しい文章が流れ込んでいる間は仕上げを止め、下書きだけを進める。

- **アプリごと**: 状態（新しく現れた文章の記録と、止めているかどうか）はアプリごとに持つ。止めるのはそのアプリの
  2 段のウインドウだけで、ほかのアプリ（前面のアプリを含む）の仕上げや下書きの順番は変えない。計画が 1 段の
  ウインドウは、どのアプリが止めていても待たせず、順番も変えない。
- **入る条件**（どちらか）: そのアプリの画面上で最初の訳（下書き）を待っている文章が `threshold`（既定 8）件以上 /
  直近 2 秒にそのアプリに新しく現れた未翻訳の文章が `threshold` 件以上。「新しく現れた」はそのウインドウの前回の
  走査に無く、どのモデルの訳もキャッシュに無い文章。ただし前回の走査にあって今回消えた文章の「その場の変化」
  （末尾か先頭に文字が足された・削られた。共通部分が 8 文字以上。消えた文章 1 つにつき 1 つ）は新しく現れたと数えず、
  元の文章の現れた順番を引き継ぐ。生成中の返信の段落が伸びていく、ターミナルで段落の上が画面外に切れる、などが
  これに当たる（1 段落が伸び続けても一時停止は起きない）。
  直前の走査で変わったばかりの文章は「下書き待ち」にも数えない（下書きが取り消され続けて停止が終わらなくなるため）。
- **止めている間**: そのアプリの 2 段のウインドウでは仕上げ（下書き済みの差し替え）のジョブを新しく始めない。
  走っている差し替えはすぐ取り消す（複数チャンクなら済んだチャンクは覚えておく。同じ文章を止めていないウインドウも
  表示していて、同じ翻訳モデルで仕上げるなら続ける）。下書き、下書きできない文章の仕上げ（1 段目として）、
  手動の翻訳は止めない。
  下書きはそのウインドウに新しく現れた順の新しいものから作る（流れる画面では古い文章ほど先に消え、上から順に
  訳すと取り消しばかりになる。実測: 0.2 秒ごとに 1 段落ずつ流れるターミナルで、上から順だと流れている間の下書きが
  すべて取り消された）。その場で変わったばかりの文章（伸びている途中の段落など）は最後に回す（次の走査でまた
  変わり、下書きが取り消されるため）。止めていないときは上から順。
- **抜ける条件**（両方）: 直近 `quietSeconds`（既定 1.5 秒）に新しく現れた文章が 1 件以下（流れが止まったか、ゆっくりになった）/
  画面上の文章すべてに下書きがある。抜けたら、画面にある文章を上から順に仕上げる（画面から消えた文章は仕上げない）。
- 流れが続く限り仕上げは止まったまま（ログが流れ続けるターミナルなど）。見えている文章は下書きで読めるので、それで正しい。
- 新しい走査が来なくても抜けられるよう、静かな時間が終わる時刻（全アプリで最も早いもの）にタイマーで再評価する。
- 時刻は壁時計ではなく起動からの経過時間（`ProcessInfo.systemUptime`）で測る（時計が戻っても停止が続かない）。
- メニューの状態表示に「仕上げを一時停止中（新しい文章が多いため）」を出す（前面のアプリ、なければ直近に走査した
  アプリの状態）。スモークテストのログにも出入りを記録する。
- 段階翻訳がオフ、または計画が 1 段のときは何もしない。数えるのも 2 段のウインドウの文章だけ。
- 一時停止を起こした「新しく現れた文章」は、停止が終わったあと次の停止の理由に数えない（静かな時間が 2 秒より短いと、
  抜けた直後にまた入ってしまうため）。最初の訳がバックオフ中の文章は「下書き待ち」に数えない（何分も止めてしまうため）。

## 6. 原文になじませる表示

訳文が「上に貼った札」に見えず、アプリ自身が表示しているように見せる。重なって読めなくなる表示は作らない。

- **原文の見た目を取る**（抽出時、`TextSegment.style` / `lineFrames`）:
  - Chromium / Electron（Slack, Discord, Claude など）: `AXTextMarkerRangeForUIElement` →
    `AXAttributedStringForTextMarkerRange` の `AXFont`（`AXFontSize`）と `AXForegroundColor`（CGColor）。
    行の矩形は `AXBoundsForTextMarkerRange` や、1 行のテキスト要素の高さから求める。実測: Claude / Discord で 12〜16pt と色が取れる。
  - ネイティブ（NSTextView など）: `AXAttributedStringForRange` の `AXFont`。
  - ターミナル: `AXBoundsForRange` の 1 文字の幅と行の高さから等幅フォントの大きさを推定し、`isMonospaced`。
    ウインドウ幅で折り返された（ソフトラップの）行は AX では 1 行として返り、その矩形は複数行の外接矩形になる。
    最長行の先頭 1 文字の矩形でセルを、最長行全体の矩形で折り返しの桁数を求め、論理行ごとに画面上の行番号を数えて
    段落の行の矩形を画面の行に分ける（AX の外接矩形と合わないときは分けない）。Terminal.app は
    `AXAttributedStringForRange` / `AXTextMarkerRangeForUIElement` に -25213 を返す（文字色は取れない）。
  - Chromium の `AXFontSize` はページのズーム（Electron のズーム設定、CSS zoom）を含まない。CJK のグリフは 1em 幅なので、
    1 行に収まった CJK の run の幅 ÷ 字数 ÷ 報告された大きさからプロセスごとのズームを推定して掛ける。
  - 段落にまとめた要素では、文字数の多い run の値を採る（リンクの run は除く。6.1）。呼び出しは段落ごとに数回までに抑え、要素 ID で覚えておく。
- **重ならない**: 1 つの段落が途中で 2 つのセグメントに割れると、Chromium の矩形（行をまたぐ run の外接矩形）が
  互いに重なる。抽出の最後に、読み順で隣り合い矩形が重なるセグメントは 1 つにまとめる。描画側でも、項目の領域が
  ほかの項目の原文の領域にかからないように切る。
  - 割れる原因: Claude のファイル参照は文中の葉の `AXButton`（DOM クラス `inline … prose-link`）。リンク風のクラスを持ち、
    frame が文字のように並ぶ葉のボタンは文の一部（インライン）として扱う。リンク風でないボタン（チップ）と、DOM クラスを
    持たないボタン（ネイティブアプリの「キャンセル」「詳細…」など）は境界のままで、障害物にもなる。
  - 段落が行の途中で割れたとき（リストの 2 行目から始まる後半など）、前の項目はその行の左側（`tail`）を持ち、
    後の項目の 1 行目はその右から始まる（背景は段付きの形）。
  - **訳さないものにもかぶせない**: 抽出は、見えているが訳さないもの（ルールの項目の外の名前・時刻・リアクション、
    除外した部分 = コードブロック・引用・ツール出力、入力欄、ボタン、画像、フィルタで落とした URL や数字、
    件数の上限で落とした段落、ターミナルの罫線・プロンプト・ツール行）の矩形を `WindowSnapshot.obstacles` に入れる。
    AX 呼び出しは増やさない（走査で既に持っている frame から、ターミナルはセルの格子から計算）。セグメントに重なるもの
    （段落の中の「(編集済)」や絵文字）は除き、ほかの障害物に含まれるものも除いて最大 200 個。それより多いときは、訳す
    セグメントに近いものを残す（走査中の記録も、いっぱいになると古いものから捨てる。チャットやターミナルの下端の入力欄が
    残る）。ターミナルの障害物は、続く行で同じ桁にあるセル（枠の左右、揃った行番号）を 1 つの矩形にまとめる。
    翻訳側は、翻訳先と同じ言語などで訳さなかったセグメントの行も加え、オーバーレイは翻訳待ちの項目と同じ扱い
    （原文を見せたまま、ほかの訳文を寄せない）にする。
  - 「マウスの下のブロック」と「フォーカス中の要素」の範囲では、訳文は読み取った要素の中に収める
    （`WindowSnapshot.axClipRect` = その要素の frame をセグメントまで広げたもの。リストの記号のようにはみ出す分を含む）。
    同じブロックのほかの段落は障害物にする。長い訳文は下の段落へ行を足さず、85% まで縮めるか末尾を「…」にする。
- **描き方**（`matchOriginalStyle`）:
  - 原文と同じ文字の大きさ・行間で、原文の 1 行目の位置から書く。ターミナルは等幅フォント。文字色は原文の色。
  - 訳文が原文と同じ（空白の違いだけ）になった項目（コード、名前など）は描かず、原文をそのまま見せる
    （翻訳待ちの項目と同じ扱い）。こちらのフォントで同じ文章を重ねても、原文を隠すだけのため。
  - 収まらないとき: ①下の空き（次の項目の手前まで、表示領域の中）へ行を足す → ②原文の 85% まで縮める →
    ③それでも入らなければ末尾を「…」にする。ほかの項目には決してかぶせない。「…」で切った訳文は、置き換え表示でも
    マウスを 0.3 秒置くと全文（と原文）を吹き出しで出す（6.1）。
    原文表示キーは訳文を消して原文を見せる。
  - 背景は原文の行の範囲だけを覆う。枠線・影なし、角丸は 2pt まで（設定の既定も上限も 2pt）、横の余白は 1.5pt。
    Chromium の run の矩形は文字の大きさと同じ高さ（em ボックス）で、ラテン文字のディセンダやアクセントがはみ出す。
    行の矩形の高さが文字の大きさの 1.15 倍以下で等幅でないときは、1 行目の上と最後の行の下を 0.22em まで広げて覆う
    （上下の項目との隙間の半分まで、表示領域の中だけ。上の項目はその分だけ手前で止める）。
  - 文字の大きさが分かっていて、枠が文字幅ちょうどの 1 行のラベルは、右へはみ出して書いてよい（同じ行の次の項目か
    表示領域の端まで）。そうしないと「OK」のような短い訳が「…」だけになる。
  - 背景色: 「背景色を画面から取る」がオンで画面収録の許可があれば、対象ウインドウ自身の画素（Plamonic の重ね表示は
    写らない）から項目ごとに背景色と文字色を測る（`ScreenColorSampling`）。測った色はその場所のものとして覚える。
    項目の位置か文章が変わっても、前に測った場所の半分以上に重なるならその色をすぐ使い、測り直しは 5 秒に 1 回まで
    （スクロールや生成中の文章の下の色は変わらない）。測ったことのない場所の項目だけをすぐ測る（0.25 秒待ち、
    動き続けても 1 秒まで）。取り込み中に動いた項目にも、今いる場所の大部分を測っていればその結果を使う。
    スクロールで重ね表示を隠している間は測らない。
    許可がなければ、原文の文字色の明るさから暗い背景か明るい背景かを決め、テーマの色を使う。Terminal.app のように
    文字色が取れないアプリでは、テーマ（「システムに合わせる」ならシステムの外観）の色になる（設定画面とガイドで
    画面収録かテーマの指定を案内する）。
    測った背景色にも「背景の不透明度」を掛ける（既定 1.0。下げると原文が透けて見える）。文字色は背景と 3:1 以上の
    コントラストがあるときだけ使う。測れなかった項目は位置か文章が変わるまで測り直さない。何にも使えなかった取り込み
    （失敗した、取り込み中にすべて動いた）のあとは 2 秒から倍々に最大 30 秒まで間を空ける。取り込みはウインドウごとに
    1 秒に 1 回まで、同時に 2 つまで、1.5 秒で打ち切る。画素はその呼び出しの中だけで使い、保存しない。
    許可の確認（`CGPreflightScreenCaptureAccess`、25〜50ms）は覚えておき、5 秒より古ければバックグラウンドで確かめ直す
    （設定画面を開いたとき、許可を求めたとき、Plamonic が前面に来たときはすぐ確かめ直す）。
  - 下書きの印は控えめに（小さな点）。オフにもできる。
- 原文の大きさが分からないとき（「原文の見た目に合わせる」がオフのときも）は、最小〜最大の範囲で枠に
  合わせる。段落が行の途中で割れているときは、大きさが分からなくても原文の 1 行目の位置から書き（中央に寄せない）、
  2 行目はその行の下から始める。前の項目は最後の行を割れた行の左側（`tail`）に書ける（縮めるときも同じ）。

### 6.1 原文を見る・リンク（`OverlayInteractionSettings`、置き換え表示）

設定は「表示」の「ポインタとリンク」（全体で 1 つ。アプリ別の上書きはない）。「原文に重ねる」で描くウインドウはすべて
これを使う（全体が「マウスの下だけ表示」でも、アプリ別に「原文に重ねる」にしたアプリを含む）。

- **ポインタを置くと原文**（`hoverOriginal`）:
  - その場で: ポインタを動かして訳文の上で `hoverDelay`（既定 0.4 秒）止めると、その項目の訳文だけが消え
    （0.12 秒で薄くなる。ほかの項目はそのまま）、下の原文が見える（原文のリンクもそのまま押せる）。ポインタが
    原文の範囲と訳文を描いていた範囲の外へ出たら、0.15 秒待って訳文に戻す（隣へ移るときにちらつかないように）。
    再描画で同じ項目が残っていれば原文のまま。項目が消えたとき、スクロールしたときは訳文に戻す。再描画で項目が
    止まったポインタの下から動いたときも、0.15 秒で訳文に戻す（その位置で新しく原文を見せることはしない）。
  - 吹き出し（既定）: 同じ条件で、原文だけを吹き出しで出す（訳文は残す。訳文を読んだまま原文と見比べられる）。
    ポインタがどの項目の外へ出ても 0.12 秒で閉じ、ほかの項目へ移ったときはすぐ閉じてその項目で待ち直す。再描画では
    項目の新しい訳文と位置に付いていき、項目が消えたとき・スクロールしたときは閉じる（スクロールが止まっても
    ひとりでには出し直さない）。原文のリンクを押したいときは、そのリンクがあった場所をクリックすれば、その場で
    原文が見える（下の「押し間違いを防ぐ」）。
  - オフ: 何もしない。
  - 「…」で切った訳文は、どのモードでも 0.3 秒で吹き出しを出し、全文の下に原文を薄い色で出す（その場で原文に
    戻すと全文が読めないため）。
  - 止まっているかの判定: 3pt 未満の動きは止まっているとみなし、それより大きく動くたびに待ち時間をやり直す。
    スクロールや再描画で文章がポインタの下に来ただけでは出さない（ポインタが動いてから止まったときだけ）。
    訳文のリンクの上では出さない（押そうとしているため）。ほかのウインドウに隠れている位置でも出さない（アプリの
    メニューの下も含む）。開いている吹き出しも、項目の上にほかのウインドウやメニューが来たら閉じる（再描画のたびと、
    項目の中で動いたときは 0.2 秒に 1 回まで確かめる）。
  - 原文を見るキー（⌥）はすべての訳文を消す。キーを離したとき、その場で見せていた原文は訳文に戻る。
  - 待ち時間は 0.1〜1.5 秒（設定画面は 0.1 秒刻み。読み込み時と変更時に範囲に収め、0.01 秒単位に丸める）。
    「何もしない」のときは待ち時間を変えられない。どのアプリも「原文に重ねる」を使っていないときはこの節を
    操作できず、その理由を書く。
- **マウスの移動**（セッション）: 移動は 0.03 秒に 1 回までオーバーレイに渡す。間引いたときは、遅れて今のポインタの
  位置を必ず渡す（止まった位置で待ち時間を数えるため。間引いた古い位置を渡すと、クリック用のパネルが先に渡した
  新しい位置が上書きされ、リンクの上なのに原文を見せてしまう）。オーバーレイが求めている間（`needsMouseMoves`:
  原文に重ねて描いた訳文があってポインタの設定が「何もしない」でない、「…」で切った訳文がある、原文を見せている
  項目がある）だけ監視する。
  走査や再描画のときに、こちらから位置を渡すことはしない（スクロールで文章がポインタの下に来ただけでは原文を
  見せないため）。
- **リンクを取る**（抽出、`TextSegment.links`）: 段落の文字のうち、`AXLink` の下（深さを問わない）と文中のリンク風
  ボタン（Claude のファイル参照、Discord のメンション。Chromium では子のない `AXButton`）をリンクとして、文中の位置
  （UTF-16）・文字・URL・原文の行ごとの矩形・要素・色・下線とともに記録する。大きな入れ物のボタンの中の段落は
  リンクにしない（いちばん内側のリンクを採る）。
  - 段落をちょうど 1 つの要素が持つとき（Slack の p-rich_text_section、Discord の messageContent）は、その要素の
    `AXAttributedStringForTextMarkerRange` を 1 回読む（呼び出しは 2 回、要素ごとに覚える）。
    リンクの文字を除いた run から段落の大きさ・色を決め、同じ run からリンクの色と下線（`AXUnderline`）も取る。
    リンクは走査で置いた位置で探す（同じ文字が前にふつうの文字として、または別の語の中にあっても取り違えない。
    位置が合わなければいちばん近いものを、語の切れ目にあるものを優先して採る）。
    そうでないときは、リンクの外でいちばん長い run を読む（リンクの色は分からない）。ネイティブの `AXTextArea` は
    `AXLink` の run を段落の見た目の候補から除くだけで、リンクとしては記録しない（呼び出しが増えるため。押し間違いも
    防げない）。読んだ範囲にリンクの run があったことだけ（`TextStyleHint.hasLinkRuns`）を描き方に渡す。
  - 段落がリンクだけのときは、リンクの run の大きさを使い、段落の文字の色は同じ大きさの隣の段落から借りる
    （なければ不明）。
  - URL はリンク要素の `AXURL`（1 回 0.05〜0.2ms、要素ごとに覚える。走査ごとに 60 個まで）。ボタンには URL がない。
    ページ内のリンクは file:// などになる。
  - 行をまたぐリンクの矩形は、同じ行の前後の run の位置で切って行ごとに分ける（関係ない文字までの外接矩形にしない）。
  - ターミナルは `NSDataDetector`（http / https / www.）で URL を見つけ（`.detected`、押す要素はない）、矩形はセルの
    格子から求める。TUI が幅で切った URL は、次の行の最初の語（末尾の句読点を除く）が URL の区切り
    （`/ ? = & % # ~ _`）を含むとき、または行がその語だけのときだけ、空白を入れずにつなぐ（括弧・引用符で始まる行や、
    ピリオド・数字だけではつながない）。
  - 正規化・段落の結合・切り詰めのあとも、位置は最終の `TextSegment.text` を指すように直す（合わなくなったリンクは
    捨てる。重なったら前のものを残す）。
  - 走査の費用（-O ビルド、リンク 13 個のテスト用のページ）: 初回は誤差の範囲、2 回目以降は +0.3〜0.4ms。
- **訳文の中のリンク**（翻訳、`OverlayItem.links`）: 原文のリンクの文字が訳文のどこに来たかを求める。見つからない
  リンクは訳文ではリンクにしない（原文から押せる）。
  - 印の付け方: 言葉のリンクは `[文字](番号)` で送り、番号で訳文の位置を取る。URL など（リンクの文字で決める。
    `.detected` は常にこちら）は印なしで送って完全一致で探し（長い語の中は探さない）、大文字小文字・全角・空白の
    違いや途中で切れた URL は原文の文字に戻す（確かでなければリンクにしない。切れた URL が原文のほかの場所にある
    URL（またはその先頭）と同じなら直さず、リンクにしない）。原文がすでに印のような書き方をしているとき、リンクの
    文字に括弧や改行があるときは印を付けない。
  - この印にした理由（実測。テスト用のチャット文 40 文・リンク 59 個、0.8B / 2B）: `[文字](番号)` は両モデルとも
    40/40 文でそのまま返り、言葉のリンク 28/28 の位置が取れた（語順が変わっても番号で対応する）。URL・@メンション・
    #チャンネル・番号・ファイル名は、印なしで 31/31 がそのまま残った（印を付けると 0.8B は @メンションを落とし、2B は
    意味を変えた）。`<a id>` も同じくらい保たれるが長く、【】・⟦⟧ は英訳で崩れた。リンクの文字だけを別に訳して
    探す方法は 26〜27/28 で、文脈で訳語が変わると外れ、リンクごとに推論が 1 回増える。
  - 費用: 印はリンク 1 つにつき入力・出力とも約 5 トークン（短い文で約 1.4 倍の時間）。言葉のリンクのない文章には
    印を付けないので、入力は変わらない。
  - 印の番号は原文の「(1)」「（2）」「3)」「①」などの番号の次から付ける（訳で全角・半角が変わっても、原文の
    番号を印の残りと取り違えないため）。3 桁に収まらなければ印を付けない。
  - 印が崩れたとき（足りない・余分・番号の重複や不明・余った括弧）は印をすべて消し、言葉のリンクは原文と同じ文字が
    残っている場合だけリンクにする。残った「(n)」を消すときも、原文にある同じ番号（全角・半角を問わない）の数だけは
    残す。生成途中の書きかけの印は表示しない。
  - フィルタと言語判定は印のない文章で行う。キャッシュは印付きの原文をキーにする（ファイルの形式はほかの文章と同じ）。
    会話履歴には印のない原文と訳文を渡す。`clickableLinks` に関係なく同じ入力にする（切り替えで訳し直さない）。
- **描き方**: 訳文のリンクの部分「だけ」を原文のリンクの色で書き、原文が下線付きなら下線を付ける。訳文のほかの
  部分は原文のリンクでない文字の色で書く（抽出で段落の色・大きさを決める run からリンクを除く。上の「リンクを
  取る」）。訳文の中でリンクが見つからなかったときは、どこもリンクの色にしない。
  - リンクの色は原文の色（背景と 3:1 以上のとき）。なければシステムのリンク色に近い色（暗い背景 #419CFF、
    明るい背景 #0068DA）。
  - リンクのある段落（ネイティブのテキスト表示でリンクの run があった段落を含む）では、段落全体で測った文字の色は
    リンクの色のことがある（長いリンクでは、いちばん多い色がリンクの色になる）。そこで、①原文の見た目に合わせて
    いて原文のリンクでない文字の色が分かれば、それを使う。②そうでなければ、リンクのない部分の文字色を別に測って
    使う（見えている行の、リンクの矩形から 3pt 離したいちばん大きなかけら。リンクの矩形があるときだけ。
    Terminal.app のように色が取れないアプリでも効く）。③それも測れなければ、段落全体で測った色を使うのは、原文から
    取れたリンクでない色に近いとき、またはそれが不明でリンクの色が分かっていてそのどれとも違うときだけ。
    ④ほかはテーマの色。
  - 訳文のリンクの文字には「/」「?」「&」「=」「-」「_」「.」の後に幅のない改行位置（U+200B）を入れて測り、描く
    （リンクの外には入れない）。長い URL は縮めたり「…」で切ったりせず、区切りで折り返す。
  - リンクのある訳文を「…」で切るときは、切り方をこちらで決めて描く（最後に見える行に残りを詰めて「…」。
    NSStringDrawing と同じ切り方で、TextKit の切り方とは違う）。描いたリンクの部分だけが押せる。
    「…」より先のリンクはリンクにしない。「…」は文字の色で描く。
- **クリック**: 訳文のリンクを押すと、原文のリンクを押したのと同じことをする（セッションの `LinkActivator`）。
  - 訳文のリンクはボタンを離したときに開く（押したのと同じリンクの上で離したときだけ。外へずらせば取り消し）。
    ⌘ クリックはふつうのクリックと同じ。右クリック・control クリックは下の「右クリック」。ほかのボタンは何もしない。
    ダブルクリックの 2 回目は無視する。覆っている原文のリンクは、押したときに原文を見せる。
  - 原文のリンクの要素に `AXPress`。押す処理は専用の直列キューで行い、メインスレッドを止めない（走査のキューには
    並べない。応答しないアプリの走査待ちでクリックが遅れないため）。
  - 要素が消えた・押せない（invalidUIElement、actionUnsupported など）ときは URL を開く。時間切れ
    （cannotComplete）のときは開かない（アプリがあとで押すことがあり、二重に開くため）。要素がないとき
    （ターミナルの URL）は URL を開く。開くのは http / https（ホストあり）/ mailto だけ（ページ内のリンクの
    file:// などは開かない）。
  - 同じリンクを 0.5 秒以内にもう一度押しても無視する（ダブルクリック）。ログに出すのは種類・結果・scheme と
    host だけ（host は private）。
  - Plamonic は前面にならず、対象のアプリのフォーカスも変えない（URL を開いたときは、開いたアプリが前に出る）。
- **リンクの上のカーソル**（`OverlayLinkCursor`）: 訳文のリンクの上では指のカーソルにする。
  - ウインドウサーバーはふつう前面のアプリにしかカーソルを変えさせず、Plamonic は前面にならない。そこで、
    ウインドウサーバーとの接続に非公開の設定「SetsCursorInBackground」を付けて、後ろにいてもカーソルを変えられる
    ようにする（`CGSSetConnectionProperty`。実行時に dlsym で探し、リンクしない。最初にリンクのパネルに入ったときに
    1 回）。実測（macOS 27.0.1）: 付けると 2ms ほどで指になり、同じカーソルを何度設定してもちらつかない。
    使えなければ（関数がない・失敗した）ログに 1 回残し、入ったときと動いたときに指にするだけにする（Plamonic が
    前面のときだけ効く）。下の「ホバーの見た目」はカーソルと関係なく出る。
  - リンクのパネルに外から入ったら、そのときのカーソル（標準のカーソルのどれか。分からなければ矢印）を覚えて指に
    する。パネルの上で動くたびにもう一度指にする（そのパネルがポインタの下のいちばん前の窓のときだけ。アプリの
    メニューが重なっていればしない）。入ってから 0.05 秒と 0.2 秒にも指にする（ポインタが入った直後に、下のアプリが
    自分のカーソルに戻すことがあるため。Chrome はポインタが出たときに矢印にする）。
  - 同じリンクの別の行や隣のリンクのパネルへ移るときは指のまま（ちらつかない）。それ以外へ出たら、覚えたカーソルに
    戻す（後ろにいるアプリのカーソルはひとりでは戻らない）。戻すのはまだ指が出ているときだけ（アプリがもう自分の
    カーソルにしていればそのまま）。表示を変えた設定（入ったとき、時間をおいて指に戻したとき）から 0.012 秒以内は、
    まだ映っていないことがあるので戻す。動くたびの設定は数えない（指はもう出ている。動くたびにカーソルを読むと
    0.3ms、ときに 9ms かかる）。前が指だったときは矢印に戻す。戻すのは標準のカーソルだけ（今のカーソルの写しは
    同じ形に戻らないため）。
  - パネルがなくなった・動いた・別のものになったとき（スクロール、隠す、⌥、原文を見せた、再描画、使い回し）は、
    出たという通知が来ない。そこで、そのとき、Plamonic のメニューを閉じたあと、グローバルの監視に動きが届いたとき
    に確かめ直し、ポインタの下にリンクのパネルがなければ戻す（0.15 秒後にもう一度確かめる）。
  - 右クリックのあとは、次に入るまで指に戻さない（予定も、動いたときも。メニューのカーソルと争わない）。出たときは
    覚えたカーソルではなく矢印に戻す（まだ指が出ているときだけ。メニューは矢印）。Plamonic のメニューを閉じたら、
    ポインタの下にリンクのパネルがなく指が出ていれば（AppKit が開いたときのカーソルに戻すことがある）、途中で
    カーソルを手放していてもリンクの前のカーソルに戻す（すぐと 0.05 秒後）。
  - 覆っている原文のリンクの上ではカーソルを変えない。パネル自身はカーソルを設定しない（カーソル矩形と
    `cursorUpdate` は前面のアプリでしか効かないため）。カーソルを変えるのはすべてこの部品を通す（テストは偽物を
    使い、本物のカーソルを変えない）。
  - 実測していないもの: Slack・Chrome・Terminal で、ポインタが入った直後や出たあとにアプリがカーソルを変える様子。
- **ホバーの見た目**: ポインタが訳文のリンクの上にある間、そのリンクのすべての行に目印を付ける（カーソルとは別。
  カーソルを変えられなくても付く）。
  - 下線のないリンクには描いたリンクの色で下線を引く。文字と同じ描き方なので、フォントの下線の位置と太さで
    文字にそろう。下線のあるリンクは色を少し強くする（背景との差を広げる: 明るい背景では黒へ、暗い背景では白へ
    30% 寄せる）。枠・背景・影は付けない（ブラウザのリンクのホバーと同じ）。
  - キャンバスで文字と一緒に描き、変わった項目だけを描き直す（1 項目 0.3〜0.8ms）。クリック用のパネルで描くと、
    窓の位置が丸められて文字とずれ、下線のあるリンクの色の変化は文字を描き直さないとできないため。同じリンクの
    行の間を動くときは描き直さない。
  - ポインタが出たとき、スクロール・隠す・⌥・原文を見せたときに消える。再描画や使い回しでパネルがなくなったり
    動いたりしたときも消える（再描画でパネルがそのままなら、ポインタはまだリンクの上なので残す）。
- **右クリック**（セッションの `LinkActivator.showMenu`）: 訳文のリンクを右クリック（または control クリック）すると、
  原文のリンクを右クリックしたのと同じメニューを出す。その項目の吹き出しが開いていれば閉じる（メニューの横や下に
  残さない）。
  - 原文のリンクの要素に `AXShowMenu`。押す処理と同じ専用キューで行い、メインスレッドを止めない。アプリが受け付け
    たら、アプリ自身のメニューが出る（Chrome・Slack・Discord・Claude なら「リンクを新しいタブで開く」「リンクの
    アドレスをコピー」など。文中のボタンやメンションではページのメニュー。どちらも原文を右クリックしたときと同じ）。
    メニューの位置はアプリが決める（Chrome は原文のリンクの中央。入らなければ左へ出す。AppKit は要素の左下。
    クリックした位置ではない）。Chrome では 0.07〜0.2 秒で出る（実測）。
    メニューが出たかは確かめない（アプリはあとから描き、Web アプリはページの中に描くので、確かめると二重に出る）。
    Plamonic は前面にならず、対象のアプリのフォーカスもスクロールも変わらない（実測）。
  - 要素がない（ターミナルの URL）、要素が消えた・メニューがない（invalidUIElement、actionUnsupported など）ときは、
    Plamonic の小さなメニューをクリックした位置に出す（Plamonic は前面にならない）:
    - 「リンクを開く」: 訳文のリンクのクリックと同じ。開けるものがなければ淡色。
    - 「リンクのアドレスをコピー」: http / https / mailto の URL があるときだけ。選んだときだけ、URL と文字列の型で
      ペーストボードに書く。
    - 「原文を表示」: その項目の原文をその場で見せる（ポインタはメニューの上にあるので、ポインタが一度項目に
      入るまでは外の動きでは訳文に戻さない。ただし項目から 200pt より離れた動き、3 秒たったあとの動きでは、
      ふつうどおり 0.15 秒で戻す。項目に入ったあとはふつうどおり、外に出て 0.15 秒で訳文に戻す）。
  - 時間切れ（cannotComplete）のときは何も出さない（アプリがあとで出すことがあり、二重になるため）。
  - 同じリンクを 0.5 秒以内にもう一度右クリックしても無視する（クリックとは別に数える）。Plamonic のメニューが
    開いている間の右クリックも無視する。
  - Plamonic のメニューは run loop のブロックから開く（MainActor の続きから開くと、開いている間すべての走査・
    再描画が止まる。実測）。閉じたらカーソルを確かめ直す。セッションを止めるときは閉じる。
  - 試すだけのとき（`--dry-run-links`）は、どちらのメニューを出すかだけを出す（要素が `AXShowMenu` を持つかだけを
    読む）。ログに出すのは種類・結果・AXError・scheme と host だけ（host は private）。
  - 覆っている原文のリンクの右クリック・control クリックは、左クリックと同じ（原文をその場で見せる。メニューは
    出さない。原文が見えたら、原文のリンクそのものを右クリックできる）。原文を見せた直後の押し間違いを防ぐ間は、
    右クリックも何もしない。それ以外の場所の右クリックは、ふだんどおりアプリに届く。
- **押し間違いを防ぐ**: 訳文で覆っている原文のリンク（とボタン）の矩形でのクリックは原文に届かせない。そこを
  クリックすると、その項目の原文をその場で見せる（ポインタが出るまで。見えている間は原文のリンクをそのまま押せる）。
  それ以外の場所（ふつうの文字の上など）のクリックはふだんどおりアプリに届く。訳文で見つからなかったリンクも、
  覆っていれば同じ扱い。
  - 原文を見せた直後（クリックでもポインタを置いたときでも）は、その項目のクリック領域がダブルクリックの間隔
    （システムの設定、0.3〜3 秒）だけ残り、クリックを受けても何もしない（押す・離すたびに延びる）。原文のリンクが
    押せるのはそのあと（ダブルクリックの 2 回目で、見えたばかりの原文のリンクを押さないため）。
  - 守れないもの: ネイティブの `AXTextArea` の中のリンク（記録しないため）、浮かせる代わりの表示のとき
    （下の「仕組み」）、64 個の上限で項目ごと外したとき（ログに出る）。
- **仕組み**: クリックを受けるのは、訳文のリンクの文字の矩形（行ごと）と、覆っている原文のリンクの矩形（項目の
  背景の範囲だけ、その項目のリンクの矩形を除く）だけの小さな透明パネル（`ignoresMouseEvents = false`、キーにも
  メインにもならない、Plamonic を前面にしない、影なし）。重ね表示の本体はクリックを通したまま。
  - パネルは重ね表示パネルの子ウインドウにする。重ね表示を対象の直上に並べ直すと一緒に付いてくる（実測: 対象を
    前に出してから並べ直しても、パネル → 重ね表示 → 対象の順）。対象の前にあるほかのウインドウより上には出ない。
  - パネルを置くのは、重ね表示が対象の直上にあると確かめたあとだけ。直上に並べられず浮かせる代わりの表示
    （`.floating`。対象のウインドウ番号が分からないとき、並べ直しが確かめられなかったとき）では置かない（ほかの
    ウインドウより上に出てしまうため。リンクは色だけで、クリックは下に通す）。
  - 透明な窓はクリックを通すことがあるので、1/255 の色で塗る。表示領域の中だけに置き、1 ウインドウ 64 個まで。
    超えたら後ろの項目から、リンクを押せなくして、リンクのある行ごとに 1 つの覆い（クリックで原文を見せる）に
    まとめる。それでも超えれば背景の行ごとにまとめる。それでも超えるときだけ項目ごと外す（覆うもののない項目から）。
    ログに残す。
  - スクロールで隠している間、一時的に隠している間、原文を見るキーを押している間、原文を見せている項目（見せた
    直後の押し間違いを防ぐ間を除く）、翻訳待ちの項目、対象が画面外のときはパネルを置かない。
  - パネルの上のスクロールはパネルが受けてしまう。最初の 1 回でそのウインドウのパネルを外し、次の走査で戻す
    （残りのスクロールはアプリに届く）。パネルの上のポインタの動きはパネル自身が追う（グローバルの監視には
    届かないため。入った・動いた・出たはカーソルとホバーの見た目にも使う）。
- **確かめ方**（スモークテストの `--show-overlays` と一緒に）: 最初に訳文に描いたリンクのパネルで、
  `--hover-first-link` はポインタが入ったことにしてホバーの見た目を `--hover-hold` 秒出す（本物のカーソルは変えない）。
  `--context-menu-first-link` は右クリックと同じ処理を行い、出たメニュー（アプリのものか Plamonic のものか、項目の数、
  出るまでの時間、原文のリンクからの位置、前面のアプリが変わったか）をログに出して 1 秒以内に閉じる（アプリの
  メニューはポップアップメニューの高さに出た新しい窓の中を当たり判定して AXMenu を探し `AXCancel`。Chrome では
  AXMenu はアプリの子にない。Plamonic のメニューは閉じる処理を呼ぶ。項目は選ばない）。あとから出たメニューも
  同じように閉じる。閉じられないメニュー（0.6 秒以内に閉じる相手が見つからない、0.9 秒たっても消えない）が残ったら、
  その場で終了コード 4 で終わる（呼び出す側がテスト用のアプリを終了する）。アプリのメニューが開いている間は、残りの
  手順を行わない。順番はホバー → メニュー → クリック（`--activate-first-link`）で、`--hover-at` はそのあと。
- `clickableLinks` をオフにすると、リンクの色付けもクリックの横取りもしない。

### 7.1 アップデート（`Updates/`）

- Sparkle 2（SwiftPM、`project.yml` でバージョンを固定）。`UpdateController` が起動と状態を持ち、Sparkle には
  `UpdateEngine` プロトコルを通してだけ触る（テストは偽物を使う）。
- **鍵があるビルドだけ**: Info.plist の `SUPublicEDKey`（ビルド設定 `PLAMONIC_SPARKLE_PUBLIC_KEY`）が空のビルドは
  アップデーターを作らない。`project.yml` では空で、リリースのワークフローだけがリポジトリの変数から入れる。
  設定の「アップデート」には「このビルドは自動アップデートしません（ソースからビルドしたため）」と出す。
- **フィード**: `SUFeedURL` は持たず、確認のたびに `SPUUpdaterDelegate.feedURLString(for:)` で選ぶ。
  安定版は最新リリースの `appcast.xml`、ベータ版はプレリリース `beta` の `appcast.xml`（最新のベータ版と最新の
  正式版を載せる）。「ベータ版を受け取る」（`receiveBetaUpdates`）が決め、未設定ならビルドに従う
  （CFBundleShortVersionString に `-beta` を含めばベータ版）。ベータ版のビルドは最初にアップデーターを始めたとき
  に `true` を保存する。ベータ版のフィードから正式版が入ったあとも、ベータ版を受け取り続けるため。
  「自動でアップデートを確認する」がオンのときに切り替えると、Sparkle の周期をやり直し
  （`resetUpdateCycleAfterShortDelay`）、数秒後に新しいフィードを裏で確認する。オフなら次の「今すぐ確認」で読む。
- **比べるのはビルド番号**（`sparkle:version` = CFBundleVersion = 履歴のコミット数）。「ベータ版を受け取る」をオフにしても古い正式版には
  戻らず、今のベータ版より新しい正式版が出たときにアップデートする（設定の脚注に書く）。
- **前面に出ない**: 1 日 1 回（`SUScheduledCheckInterval`）、確認してよいかは聞かない（`SUEnableAutomaticChecks`）。
  定期の確認で見つけたバージョンは、Sparkle の gentle reminders でメニューの「アップデートがあります（<バージョン>）」にだけ出す
  （`standardUserDriverShouldHandleShowingScheduledUpdate` が false）。ウインドウを出すのは、利用者がその行、
  「アップデートを確認…」、「今すぐ確認」を選んだときだけで、そのときにアプリを前面に出す。
- **検証**: 更新アーカイブ（zip）の EdDSA 署名を `SUPublicEDKey` で確かめる。`SUVerifyUpdateBeforeExtraction`
  は使わない（使うと zip では EdDSA の鍵を替えられなくなる）。鍵か Developer ID 証明書のどちらか一方なら、
  1 回のアップデートで替えられる。
- **`--update-probe <URL|stable|beta>`**: メニューバーのアプリを起動せず、ウインドウのないユーザードライバで 1 回
  確認し、見つけたバージョンをダウンロードして「インストールできる」まで Sparkle に確かめさせてから、インストールを取り消して
  終わる（終了コード 0 確認済み、1 なし、2 エラー、3 始められない、4 時間切れ）。セッション、初回の案内、権限の
  確認は始めない。

## 9. ブラウザ拡張機能（`Bridge/`）

Safari と Chrome の Plamonic 拡張機能が、YouTube の字幕などをこの Mac の PLaMo で訳すための受け口。拡張機能は
ページから文章を集めて表示し、翻訳はアプリが行う。設定「一般」の「ブラウザの拡張機能に翻訳を提供する」
（`acceptBrowserExtensions`、既定オン）がオフのあいだはソケットを開かない。「翻訳を有効にする」（⌃⌥T）は画面の
オーバーレイのスイッチなので、拡張機能には効かない（拡張機能は自分のオン・オフを持つ）。オフにしても文書は忘れない。

### 9.1 経路

```
拡張機能（Safari・Chrome で共通の MV3 コード）
  ├ Safari: browser.runtime.sendNativeMessage → 同梱の .appex（サンドボックス）
  └ Chrome: chrome.runtime.sendNativeMessage → Native Messaging ホスト（.app 内のヘルパー）
      ↓ 1 行 1 リクエストの JSON（Unix ソケット）
Plamonic: BridgeSocketServer → BridgeService → TranslationCoordinator の「文書」
```

- ソケットは App Group `NBDP5VK335.io.smdr.Plamonic` のコンテナの `bridge.sock`。サンドボックスの Safari 拡張が
  届くのはここだけ。グループ ID がアプリの署名のチーム ID で始まるときだけ使い、そうでないビルド（アドホック署名、
  別のチーム）は `~/Library/Application Support/Plamonic/bridge.sock` に置く（グループのコンテナに触ると macOS が
  ほかのアプリのデータへのアクセスを確認するため）。そのビルドでは Chrome だけが使える。
- Safari の拡張機能はアプリに同梱する `Contents/PlugIns/PlamonicSafariExtension.appex`（サンドボックス、同じ App Group）。
  中身は `BrowserExtension/dist/safari`（ビルドフェーズ `scripts/build-web-extension.sh` が入れる）と、メッセージを
  そのままソケットへ渡す `SafariWebExtensionHandler`（`BridgeClient` を使う）。チームの署名がないビルドでは
  App Group を使えないので、拡張機能は `appNotRunning` を返す。
- 権限 0600 で、つなげてきたプロセスの uid が同じときだけ受ける。1 つの接続で何行送ってもよく、最後の行は改行が
  なくても（送り側が書き込みを閉じれば）答える。1 行は 8 MB まで。60 秒何も来ない接続は切る。
- 検証（フェーズ 0）の結果と、拡張機能側で気をつけることは `Tools/extension-spike/README.md`。
- 拡張機能の構成と機能の足し方は [BrowserExtension/README.md](../BrowserExtension/README.md)。

### 9.2 メッセージ（`BridgeProtocol`、プロトコル 1）

リクエストは `{"id": 任意, "type": …}`。応答は同じ `id` と `ok` を持ち、失敗なら `error`
（`badRequest` / `unknownDocument` / `disabled` / `tooLarge`）と `message`。

| type | 内容 | 応答 |
| --- | --- | --- |
| `hello` | 起動しているか、何ができるか | `protocol`、`version`、`enabled`、`targetLanguage`、`ready`（モデルがあるか）、`features`（`documents`、`translate`、`sites`） |
| `sync` | 文書の文章（`items: [{id, text}]`、初回と変わったときだけ）、`focus`（表示中の項目の id）、`urgent`（focus から何件を急ぐか、既定 3、最大 20）、`visible`（画面に見えている項目の id、上から順。60 件まで。あればこちらを急ぐ）、`kind`、`context`、`sourceLanguage`、`want`（結果が欲しい id、省略で全部） | `results: [{id, state, text?}]`（state は pending / draft / final / failed / skipped）、`progress: {done, total}`（字幕は focus から先、ページは全部） |
| `close` | 文書を閉じる（タブを閉じた、別の動画に移った） | — |
| `translate` | `texts`（20 件まで）をすぐ訳す（選択範囲など） | `translations`（失敗したところは null） |
| `site` | `url` のページの Webサイトの設定（9.4） | `site: {pattern, name, mode, include, exclude, source}` |
| `sites` | 動作が自動のサイト | `sites: [...]`（`site` と同じ形） |
| `setSite` | `url` のサイトの動作を `mode`（off / automatic / manual）にして設定に保存する（拡張機能のメニュー） | `site` |

- 文書は `client`（`safari` / `chrome`）と `document`（例 `yt:<動画 ID>`）で区別する。アプリが再起動したり、
  5 分間問い合わせがなくて忘れたりした文書に `items` なしで `sync` すると `unknownDocument` を返すので、
  拡張機能は `items` を付けて送り直す。
- `kind: "captions"` は 1 本の話の続きなので、直前の行の訳を会話履歴として渡す。`"page"`（ほかの値も）は渡さず、
  先読みはページ全体（focus より前も）に及ぶ。
  `context`（動画のタイトルとチャンネルなど）は PFML3 の context に、`sourceLanguage`（BCP 47）は PLaMo の言語コードに
  直せるときだけ翻訳元言語にする。
- Safari の `sendNativeMessage` は 1 回の依頼に 1 回答えるだけなので、結果は拡張機能が取りに来る（ポーリング）。

### 9.3 文書の翻訳順（`TranslationCoordinator`）

文書は全部の文章を一度に受け取り、あとは `focus` を動かす。ウインドウと同じく、手が空いたときに最新の状態から
次の 1 件を選ぶ。

1. 手動の依頼（`translateOnce`、`translate`）
2. 文書の画面に見えている項目（`visible` の順。なければ focus から `urgent` 件）のうち、まだ訳のないもの。下書きモデルがあれば下書きで
3. ウインドウの初回の翻訳
4. ウインドウの仕上げ
5. 文書の先読み: 急ぐ項目の仕上げ、focus から後ろを順に、ページならそのあと focus より前を、仕上げのモデルで直接
   （時間があるので下書きを挟まない）

字幕では focus より前の行は訳さない（もう表示し終えた）。ページでは、見えている段落が固定のヘッダーと本文の途中のように
離れていても `visible` で正しく急げる。設定はグローバル設定に、文書の `context` と `sourceLanguage` を
重ねたもの。キャッシュ、失敗時の待機、長い文の分割、仕上げの途中で新しい急ぎの文章に譲るのはウインドウと同じ。
文書を閉じる・忘れると、その文章だけが待っていた翻訳は止める。

### 9.4 Webサイトの設定（`SiteProfile`、設定「Webサイト」）

拡張機能がサイトごとにどう訳すかは、アプリの設定で一元管理する（ブラウザごとには持たない）。アプリの設定
（`AppProfile`）と同じく、プリセット → 利用者が編集したもの（settings.json の `sites`）の順に重ね、プリセットと同じに
戻した設定は保存しない。

| 項目 | 内容 |
| --- | --- |
| サイト（`pattern`） | ホスト名（`www.youtube.com`）、`*.` を付けたドメイン（`*.wikipedia.org`、そのドメインとサブドメイン）、後ろにパスの先頭（`github.com/apple`）。URL に合うもののうち、ホスト名がそのまま一致し、パスが長いものほど優先 |
| 動作 | 自動（ページを開いたら訳す）／手動（拡張機能のメニューの「このページを翻訳」）／オフ（訳さない）。設定のないサイトは手動でページ全体 |
| 翻訳する場所・しない場所 | CSS セレクタ（1 行に 1 つ）。する場所が空ならページ全体。する場所に合う要素は、行の中に表示される要素でも 1 段落として扱う。読めないセレクタは使わない |
| 翻訳先言語・文体・文脈 | 全体の設定を上書き。文脈はページのタイトルの前に付ける |

- プリセット: YouTube（タイトル、説明、コメント）、X、Reddit、GitHub、Wikipedia、Hacker News。
- 拡張機能はページを開くと `site`（URL）で設定を聞き、`sync` / `translate` には `url` を付けてサイトの上書きを適用させる。
- ツールバーのメニュー: 「このページを翻訳」（その場で 1 回）、「このサイトを自動で翻訳」（`setSite` でアプリの設定を
  自動にし、ブラウザの許可を求め、このページも訳す）、自動のサイトでは「このサイトの自動翻訳を一時停止」／「自動翻訳を
  再開」（一時停止は拡張機能がサイトごとに覚え、アプリの設定は自動のまま）。
- 自動のサイト: 拡張機能はサイトに入る許可がないとページを開いたことも知れないので、自動のサイトで初めてメニューを
  開いたときに一度だけ許可を求める（`permissions.request`、クリックが要る）。
  - 「すべてのサイトで自動翻訳を使う」（おすすめ）: content script をすべてのページに登録し、ページを開くたびにアプリに
    設定を聞く。以後はアプリで自動にするだけで、次に開いたページから訳される。自動でないページでは何もしない。
  - 「このサイトだけ許可」: `sites` で自動のサイトを聞き、許可されたサイトだけに登録する。
  - 登録は `scripting.registerContentScripts`。YouTube の字幕の翻訳はサイトの動作とは別（オフでも字幕は訳す）。
